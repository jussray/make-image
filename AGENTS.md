# Cinematic Composition — Agent Design Standard (staged)

Applies to **authorized** app, game, website, storyboard, content visual, page, screen, and UI agent handoffs in this repository. Build **one cohesive cinematic composition** across the relevant user journey — not disconnected template blocks. This is a draft instruction, **not** a merged change, live visual redesign, agent runtime installation, or publication permission.

1. Inspect this product's real source, approved original design images, brand assets, visual fingerprints, existing tokens, and actual routes first. Preserve the **product's own** colors, characters, typography, art, environment, sound, and voice. Do not substitute default parent-brand styling or mistake scaffolding wireframes for visual canon.
2. Define a coherent scene thesis: purpose, focal point, depth, atmosphere, hierarchy, negative space, primary CTA, and supporting content. Carry the same visual story through navigation, content, relevant auth/commerce/settings states, mobile and errors, not just the hero.
3. Make lighting, effects, animation and audio purposeful; honor keyboard/screen readers, contrast, focus, responsive touch, reduced motion, performance, consent, and no forced autoplay/flashing.
4. Reuse established functionality and apply the smallest scoped, reversible edit. Do not alter server authority, payments, privacy, secrets, permissions, real-world claims, archives, or unrelated product behavior.
5. Before marking a screen PASS, collect source brand reference, branch and exact head, real browser/game captures, interaction tests, responsive, reduced-motion and accessibility checks, plus performance evidence. Keep source staging, tests, browser verification, runtime adoption, deployment, and outcome independently classified. UNKNOWN is not PASS.
6. Never auto-approve, merge, deploy, publish, access private data, spend or delete because this instruction exists; stricter repo and founder gates govern.
